Engineering reference · data flow

FruitFlyCCTV

A security-camera alert system that runs an actual Drosophila looming-escape circuit on the video feed — LC4 and LPLC2 into the Giant Fiber (DNp01) — with connection weights read directly from synapse counts in the MaleCNS v1.0 connectome, not fitted to data. Local CPU, no GPU, no training, no cloud.

Data flow

From synapse counts to an alarm

Two pipelines. The top lane runs once, offline, and turns ~1 GB of raw connectome tables into a small signed weight matrix. The bottom lane runs on every video frame, using those weights to turn a camera image into a NOTICE or ALARM event.

Connectome subgraph extraction

Loads the three MaleCNS v1.0 tables, keeps only the 23 cell types the circuit cares about (LC4, LPLC2, LC11, LPLC1, LPLC4; T4a–d, T5a–d; HSE/HSN/HSS, VS; DNp01/02/03/04/06/11), signs every edge by its presynaptic neuron's consensus neurotransmitter (GABA/glutamate → −1, acetylcholine/dopamine/serotonin/octopamine → +1), drops edges under 3 synapses, and aggregates the remainder into a type-level matrix.

01

Retina — motion front end

src/motion.py — class Retina, called once per frame

Converts each frame to grayscale, downsamples to a 48×48 grid (coarser than 1080p on purpose — closer to fly ommatidial acuity), and contrast-normalises it. Farneback optical flow against the previous frame gives a global mean vector μ — the self-motion signal, the HS/VS analogue — and the residual (flow − μ) weights a frame-difference energy map. An adaptive median + 6·MAD threshold picks out the blob that actually stands out from the scene; its bounding box gives the subtended angle θ and area, assuming a 60° field of view.

Input 
frame: ndarray (H×W×3, BGR)
t: float — seconds
Output 
{ theta: float   # deg, blob extent
  area: float    # fraction of frame
  flow: float    # global flow magnitude
  warm: bool     # <1s since start
  mask: ndarray }# blob mask, for viz
02

Circuit — looming model & alert decision

src/circuit.py — class LoomingCircuit, method .step()

LC4 is a leaky high-pass filter on expansion velocity dθ/dt (τ = 0.10 s). LPLC2 is a Gaussian tuned to angular size, peaking at 40° (published in Ache et al. 2019). A cross-term LPLC2×LC4 mirrors the LPLC2→LC4 synapse. The three sum with connectome-derived weights and pass through a supralinear exponent (1/1.4) to give DNp01's raw drive, which is then scaled by a habituation gain (decays 0.35/s while firing, recovers 0.08/s, floor 0.20) and a wide-field flow-suppression term that discounts self-motion. DNp01 ≥ 0.65 with θ ≥ 25°, outside a 2 s refractory window, fires ALARM; ≥ 0.30 fires NOTICE.

Input 
t: float
theta_deg: float
blob_area_frac: float = 0.0
flow: float = 0.0
Output 
{ LC4: 0–1,  LPLC2: 0–1
  DNp01: 0–1,  gain: 0–1
  suppress: 0–1
  event: null | "NOTICE" | "ALARM" }

Inside circuit_weights.json

How its values were chosen

Every number in the file is a rollup of the raw connectome tables, not a hand-picked constant — this is the arithmetic scripts/extract_subgraph.py does to get there, and what's actually used downstream.

Which 23 types, and why

Rather than keep all 166,700 neurons in MaleCNS v1.0, the extractor filters annotations down to TYPES — one named list, chosen by role in the circuit:

GroupTypesRole
Looming channelsLC4, LPLC2 drive DNp01 directly — the two terms in Ache et al.'s published model
Contrast / controlLC11 a small-object detector, kept as a check that it contributes ~0 to DNp01
Sibling LPLCsLPLC1, LPLC4 extracted for completeness; not yet wired into the running model
Motion input layerT4a–d, T5a–d the Reichardt-correlator layer that feeds LC/LPLC upstream, kept for a future full front end (§ known limitations)
Wide-field / self-motionHSE, HSN, HSS, VS the biological HS/VS signal — what motion.py's flow term is standing in for
Descending outputsDNp01…DNp06, DNp11 DNp01 is the Giant Fiber, wired to ALARM; the rest are un-used NOTICE-tier candidates

The weight threshold — min_synapse_weight = 3

Across the full connectome the median edge carries a single synapse. A one- or two-synapse connection is as consistent with segmentation noise as with a real one, so edges under 3 synapses are dropped before anything is aggregated. Lower it and the matrix fills with noise; raise it and small-but-real channels (like the LPLC2→LC4 cross-term, 1,780 synapses) start to look arbitrary rather than measured.

Sign — excitatory vs inhibitory

Each neuron's own consensus_nt (from the neurotransmitter table) is mapped to a sign: GABA and glutamate → −1 (inhibitory), acetylcholine, dopamine, serotonin and octopamine → +1 (excitatory). type_sign in the JSON is the median sign across all neurons of that type. The extractor now fails loudly rather than guessing — if any tracked neuron lacks a mapped transmitter it prints a warning naming the type before defaulting it to +1, and otherwise says so explicitly. In this subgraph every one of the 23 types came back cholinergic: type_sign is +1.0 across the board, so signed currently equals synapses for every edge — a measured result, not an assumption the extractor makes going in.

The edges matrix — synapses, signed, n_edges

The ~151M-row weight table is filtered to edges above the threshold whose endpoints are both in the 14,301-neuron subgraph, each body ID is mapped to its cell type, and rows are grouped by (type_pre, type_post). Per group: synapses sums the raw synapse counts, signed sums synapses×sign for the presynaptic neuron, and n_edges counts how many distinct body-to-body connections were collapsed into that one type-pair. neuron_counts is a plain per-type tally after filtering — used for reporting, not read by the runtime model.

What circuit.py actually reads

Of the hundreds of type-pairs in the file, LoomingCircuit.__init__ reads exactly three — LC4→DNp01, LPLC2→DNp01 and LPLC2→LC4 — to compute w_vel, w_size and w_cross (see the constant table below). The T4/T5, HS/VS and other DNp edges ship in the file for a future full front end but aren't consumed by the model running today.

Stage 01, in depth

Optical flow — what it does, and how

Retina runs one optical-flow computation per frame and splits its result into two very different signals: one reshapes which pixels count as "the blob," the other later gates whether the circuit is allowed to alarm at all.

Dense flow vs. frame difference

Frame differencing (|gf − prev|) only says a pixel's brightness changed. Optical flow says which direction and how far it moved. cv2.calcOpticalFlowFarneback estimates this densely — a (dx, dy) vector for every one of the 48×48 grid cells, not just a handful of tracked corners — by fitting a local polynomial to each cell's neighbourhood in both frames and solving for the displacement that best explains the change between them, over a small image pyramid so both slow, large motion and fast, fine motion are caught.

fl = cv2.calcOpticalFlowFarneback(prev_small, small, None,
    0.5, 2, 9, 2, 5, 1.1, 0)

Splitting the field: self-motion vs. object motion

The raw field mixes two things together: the camera's own motion (shake, pan, vehicle vibration) and whatever is actually moving on its own in the scene. motion.py separates them with one line each:

QuantityComputed asRepresents
μ (mu)fl.mean(axis=0) the whole-field average displacement — one shared vector if the entire 48×48 grid is drifting together
residualfl − μ what's left, per cell, once that shared drift is subtracted — motion that disagrees with the crowd

Where each one lands

Inside Retina — reshaping the blob. The residual's magnitude is normalised to 0–1 (rmag) and used to reweight the plain frame-difference accumulator: energy = accum × (0.3 + 0.7·rmag). A pixel changing brightness in lock-step with the rest of the scene (small residual, close to μ) is discounted to about 30% of its raw signal; a pixel moving independently of that shared drift keeps up to 100%. This is what stops a swaying whole scene, or the camera shaking, from being handed to the threshold step as "the" moving object.

Inside Circuit — gating the alarm. The magnitude of μ alone, flow_mag, is passed through unrelated to the blob mask, all the way to LoomingCircuit.step(), where suppress = 1 / (1 + (flow / FLOW_SUPPRESS)²) discounts DNp01's output the more the whole scene is judged to be translating — independent of whatever blob was actually found. Same optical-flow computation, two separate jobs: one shapes perception, the other gates the decision.

In the fly, this split is the literal job of the HS/VS lobula-plate tangential cells — wide receptive fields that pool local elementary-motion signals to read out the whole-scene optic-flow patterns produced by the fly's own movement, used for flight stabilisation, entirely separate from the narrow-field looming pathway. The μ/residual split here is a standard-CV stand-in for that same separation, not a T4/T5 correlator array — see the honest framing in § known limitations.

Stage 02, in depth

How the final constants were chosen

Every value tagged empirical in the table below wasn't fit to data by an optimiser — it was set by hand against two contrasting clips and an ablation harness that isolates one mechanism at a time, then judged against a stated acceptance rule.

The two calibration clips

CCTV.mov — 78 s, 1,118 frames, cropped home security footage containing a real approach. WAYMO.MOV — 30 s, 895 frames, in-vehicle dashcam footage: constant self-motion, no looming threat, exactly the kind of clip a naive motion detector floods with false alarms. Both clips are things an ordinary detector already thought worth alerting on — so a constant is judged not by whether the circuit fires, but by whether it fires on the right one.

The ablation loop

Both clips are run through the full circuit, then re-run with exactly one mechanism disabled at a time. If disabling a mechanism doesn't move the alarm count in the direction it should, either the constant governing it is wrong, or — as turned out to be the case for flow suppression — it isn't engaging at all.

Constant by constant

ConstantHow it was set
SIZE_WIDTH_DEG 18° width of the Gaussian around the published 40° peak — narrow enough that LPLC2 doesn't respond to any large object, wide enough to still respond near the approach clip's actual peak angular size
VEL_TAU .10s / VEL_NORM 90°/s high-pass time constant and normalisation picked so LC4 saturates near the dθ/dt values actually measured on the approach clip, not from a formula
SUPRALINEAR 1.4 supralinear summation is reported in Ache et al.; 1.4 is this project's own exponent, chosen so two weak channels can co-activate DNp01 without either alone crossing threshold
MAD threshold k = 6.0 raised by hand against real background clutter until stationary-scene noise stopped tripping the blob detector
ALARM / NOTICE = .65 / .30 set relative to the DNp01 peaks actually observed on the approach clip (≈0.8–1.0) versus background motion, leaving headroom between the two tiers
MIN_ALARM_DEG = 25° the size gate — the ablation table above shows removing it lets a 20° spurious blob alarm on velocity alone; 25° sits just above that
HAB_DECAY/RECOVER/FLOOR = .35/.08/.20 per s tuned so habituation visibly kicks in within a few seconds of repeated motion and recovers over a comparable gap — no published timescale to anchor to
FLOW_SUPPRESS = 2.5 an initial guess for the flow scale that should fully gate the alarm; the ablation table above shows it's too high for the flow magnitudes actually observed — a live, not-yet-closed retune, target ≈0.5 (§ known limitations)
REFRACTORY_S = 2.0s cooldown long enough that one continuous approach isn't double-counted as several separate alarms

Known limitations

Documented, not hidden

Habituation over-suppresses

Zero alarms on a real approach clip isn't selectivity — the mechanism is eating genuine events along with the nuisance ones. Needs labelled ground truth to tune against.

Flow suppression may be inert

FLOW_SUPPRESS=2.5 against an observed flow range with a much lower median means the wide-field self-motion gate barely engages on some footage.

θ is quantised

A 48×48 grid gives 1.25°/cell, so dθ/dt carries quantisation noise alongside real motion.

Fixed 60° FOV assumption

Angular size is only as correct as the configured field of view — not yet set per clip.

Small evaluation set

Two clips, no labelled ground truth yet — a result, not a benchmark.

Monocular depth ambiguity

"Small and close" vs "large and far" is unresolved; flies disambiguate with panoramic vision and ecological priors this system doesn't have.
